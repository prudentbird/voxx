## Findings considered and rejected

Recorded so nobody re-audits them:

- **Shiki/unified processor rebuilt per document** (`render.ts:93`): verified
  `@shikijs/rehype` uses `getSingletonHighlighter` — grammar/theme loading is
  a one-time process-wide cost, not per-document. Residual per-doc pipeline
  construction is cheap. Optional future micro-win: pass explicit `langs` to
  avoid eagerly loading every bundled grammar.
- **Web app loads full corpus per page / llms-full route** : `apps/web`
  wraps `getPosts`/`getConfig` in `"use cache"`
  (`apps/web/src/app/docs/_voxx/data.ts`) and routes are statically
  generated; not a real cost.
- **`getPost` is O(n) over the corpus** (`content.ts:219-231`): acceptable
  for a static-generation tool; the all-posts load is also load-bearing for
  draft-visibility rules (documented in-code at `content.ts:225-226`).
- **`render.ts` "monolith" refactor**: speculative extensibility, HIGH risk
  on the hottest path, no current demand. Not worth doing.
- **`buildSeo` called per post in build loop**: pure function, no I/O —
  fine as is.
- **tsgo (`@typescript/native-preview`) for typecheck**: deliberate
  early-adopter choice, pinned to an exact dev version; CI breakage risk is
  contained by the pin.
- **Next.js 16 + turbopack in `apps/web`**: intentional dogfooding.
- **Dev-server path traversal**: guard at `dev.ts:36,42`
  (normalize + strip leading `../` + `startsWith(outDir)` on a `mkdtemp`
  dir) verified adequate; plan 004 adds regression tests rather than a
  redesign.
- **Raw-HTML-in-markdown XSS**: `allowDangerousHtml` + `rehype-raw` is the
  advertised "GFM + raw HTML" feature (README:14); authors are trusted by
  design in a file-based CMS.
- **"Feeds/SEO tests are smoke-only"**: overstated — `core.test.ts` (511
  lines) asserts real structure (TOC, ordering, nav trees, draft rules,
  asset resolution). Optional future nicety: XML well-formedness parse of
  RSS/sitemap output.
- **Date fallback to filesystem mtime**: already warns loudly and documents
  the CI-churn rationale (`content.ts:104-110`). The silent
  invalid-date→`new Date()` fallback in `util.ts:97-105` is cosmetic; revisit
  only if feed dates misbehave in practice.
- **CORRECTNESS-02 (pager bounds "inconsistency")**: audited claim didn't
  hold up — both code paths handle the boundary correctly.
- **Sparse `util.test.ts` (CLI)**: the module is 74 lines of trivial
  helpers; plan 001 adds `yamlValue` tests, which covers the part worth
  testing.
- **Pre-commit hooks, README polish (tsgo note, turbo-cache note,
  `.env.example`)**: preference/polish; not planned.
- **Root `CLAUDE.md`/`AGENTS.md`** (finding #6, DX): real and recommended,
  but the maintainer deferred it this round. Revisit next session —
  cheapest-possible win for agent-executed work like these plans.
